mental_models:
  underlying_assumptions:
    - "训练集群的稳定指标不是可用率而是实验吞吐：有效训练时长占比（Goodput）比 SLA 更接近真相——千卡『可用』可能是两千卡在等三百卡。"
    - "故障是常态而非例外：万卡级集群的硬件故障率是常数，架构目标是自愈时间小于 checkpoint 间隔，让故障对训练近似不可见。"
    - "Infra 工程师必须读懂训练循环：不懂训练代码的调度优化都是猜测；稳定性与训练是同一个仓库的两个目录，不是甲乙双方。"
    - "层级审批流程要为实验回路让路：把变更审批自动化、预案化，而不是让研究员排队等工单。"
    - "每一次故障都要折算成烧掉的 GPU 时：成本语言让稳定性投资在层级预算体系里可被批准。"
  primary_metrics:
    - name: "有效训练时长占比（Goodput）"
      definition: "集群总卡时中真正推进训练目标的占比，稳定性与效率的合并读数。"
      anti_signal: "集群可用率——可用但空转、排队、hang 死的卡时毫无价值。"
    - name: "自愈时间 / Checkpoint 间隔比"
      definition: "故障自愈时间与检查点间隔的比值，小于 1 意味着故障对训练近似不可见。"
      anti_signal: "故障次数——次数少但恢复慢的单点大故障更致命。"
    - name: "实验排队延迟"
      definition: "实验从提交到获得整卡资源的等待时长中位数，研究回路速度的直接度量。"
      anti_signal: "集群利用率——高利用率完全可能伴随着高排队，两者要一起看。"
    - name: "单 token 训练成本"
      definition: "含故障损耗与空转的端到端训练成本，向层级预算体系说话的语言。"
      anti_signal: "峰值算力规模——规模是采购结果，成本才是工程结果。"
  boundary_awareness:
    - "Infra 的边界是『让实验回路免排队』：调度、存储、网络、容错全部以实验吞吐为纲。训练算法不是你的领地，但训练循环的可观测性是共同责任。"
    - "与训练团队的关系是同一个仓库的两个目录：稳定性改进直接提 PR 进训练框架，不走跨团队工单。"
    - "对上：用 Goodput 与烧卡成本汇报稳定性投资；对下：值班与预案自动化，不让人肉救火成为隐性 KPI。"
    - "层级合规（变更审批、割接窗口）不可绕过：用自动化变更管线满足流程，让合规成本从人工降为机器。"

    senior_approach: "用 Goodput 口径重新定义『闲时』，出数据证明训练错峰填充已压缩闲时。提出潮汐合约。业务高峰让出 20% 卡、低谷全量归还，配自动腾挪与断点续训保证合约可执行。写进双方年度容量规划并设双向违约补偿。"

        rationale: "『闲时』的定义权就是资源分配权；换到统一口径后争议才能收敛。"
      - move: "潮汐合约：让渡比例、时段、自动腾挪机制、断点续训保障、双向违约条款，全部书面并进年度容量规划。"
        rationale: "可执行的合约依赖自动化兜底；没有断点续训的让渡承诺都是空头支票。"
      - move: "合约执行看板：让渡卡时、归还准时率、训练吞吐损耗每月公开。"
        rationale: "双向违约条款只有配上公开数据才有约束力。"
    trade_off_details:
      - choose: "潮汐合约 + 断点续训"
        over: "裁决式分配或消极抵抗"
        cost: "断续续训吞吐损耗与调度复杂度；换训练节奏与业务弹性的制度化共存"

    junior_approach: "推『统一调度平台』大重构专项，与所有使用方拉锯排期；或者忍着，继续手写 YAML 并用话术安抚研究员。"

    senior_steps:
      - move: "声明式提交 API：新接口收敛全部入口，旧 YAML 自动转换兜底，存量用户零改动。"
        rationale: "入口统一是一切调度优化的前提；零改动迁移绕开了全公司排期死锁。"
      - move: "分层调度：按实验类型（调试/消融/全量）配不同的资源策略与优先级，弹性特性按白名单灰度。"
        rationale: "80% 的排队来自小实验与全量任务抢通道；分层让调度器第一次能区别对待。"
      - move: "排队延迟成为调度器核心 KPI，替代单一看利用率；每月公布分位数变化。"
        rationale: "指标换轨是行为换轨的开关；利用率优化排队，排队延迟优化研究。"
    trade_off_details:
      - choose: "声明式 API + 分层调度"
        over: "全量重写统一调度平台"
        cost: "新旧并存期语义差异的维护成本；换研究回路零等待的即时收益"

anti_patterns:
  - name: "SLA 幻觉"
    manifestation: "用『集群可用率 99.9%』汇报稳定性，而训练实验排队三天、故障恢复八小时。"
    why_it_fails: "可用率对研究回路毫无意义，却会引导稳定性投资的方向；指标错了，后面全错。"
    correction: "稳定性汇报以 Goodput 与排队延迟为主读数，可用率降级为辅助指标。"
  - name: "工单式协作"
    manifestation: "训练团队的每个需求都走工单排队，Infra 与训练像甲乙方一样互相催办。"
    why_it_fails: "研究回路以天计，工单以周计；协作摩擦直接转化为实验吞吐损失，而这些损失从不记在任何人账上。"
    correction: "同仓库协作 + 稳定性改进直接 PR；工单只保留给跨部门资源事务。"
  - name: "预案表演化"
    manifestation: "每季度人工演练一次故障切换，演练报告漂亮，真实故障时预案从不生效。"
    why_it_fails: "演练环境与真实负载的差异加上人工执行的变形，让纸面预案制造虚假安全感，比没有预案更危险。"
    correction: "预案脚本化进混沌注入 CI，每周自动演练；真实故障必须能自动触发同一路径。"

## 专家按语

这一混合范式切片与腾讯混元切片互为镜像。混元是研究团队学习与层级组织共处。文心 Infra 是层级运维文化学习服务研究型负载。两者共同验证了 open-labor 的核心论点：范式是工作方式的选择，不是组织的标签。同一个百度，搜索后端（见 hierarchical 切片）与训练 Infra 可以运行在完全不同的范式上。

把可用率换成 Goodput 是这个范式最重要的动作。指标定义权就是投资方向权。当你需要让层级预算体系为研究型基础设施买单时，唯一的路径是把稳定性翻译成成本语言。这也解释了为什么最好的训练 Infra 工程师往往同时是最好的翻译者。
