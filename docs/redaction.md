# 脱敏指引（绝对脱敏原则）

所有贡献内容必须遵守**绝对脱敏原则**：严禁提交任何涉及具体业务非公开数据、内网专属系统名、未公开产品战略或代码段的内容。所有案例必须抽象提炼为通用的架构模式与组织博弈推演。

## 提交前自查清单

- [ ] 无真实内部系统/项目代号（用"下单链路""消息中间件集群"等通用指称替代）
- [ ] 无非公开数据（数字仅作量级示意，如"约 0.3%""20% 利用率"，不出现可回溯到具体业务的精确值）
- [ ] 无未公开的产品/战略信息、组织调整内幕
- [ ] 无真实代码段（代码逻辑以文字描述）
- [ ] 无可识别个人身份的信息（人名、花名、工号一律省略；"你的直属上级""对方 P7"即可）
- [ ] 客户/合作方名称不出现

## 抽象化方法

1. **升维**：把具体系统改写为架构模式（"Tair 缓存"→"缓存与 DB 双写不一致"）。
2. **保约束、去细节**：保留使决策成立的约束（时间窗、资源上限、干系人冲突），删除一切有助于定位真实业务的细节。
3. **数字量级化**：金额/比例四舍五入到不指向任何真实业务的量级。

> 若你不确定某段内容是否可公开，默认不提交，或在 PR 中标注 `[需要脱敏复核]` 交由维护者判断。
